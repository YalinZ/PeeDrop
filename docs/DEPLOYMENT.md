# 部署与资源准备

## 配置

先运行 `node scripts/setup-local.js`，按 README 填写本地配置，再导入微信开发者工具。项目配置和运行配置都不应提交到 Git。

## 云函数

在实际使用的资源方云环境中，对 `walkStats`、`clearMarkers` 分别执行“上传并部署：云端安装依赖”。不要把它们误部署到调用方默认环境。两个目录各自的 `package.json` 声明依赖，无需上传本地 `node_modules`。

`clearMarkers/config.json` 定义每五分钟的定时触发器。部署后在控制台核实触发器已创建、日志正常且仅清理过期标记。

## 数据库

创建以下集合：

| 集合 | 用途 |
| --- | --- |
| `pd_users` | 宠物档案 |
| `pd_markers` | 地图活动标记及过期时间 |
| `pd_walk_sessions` | 遛狗会话版本与统计状态 |
| `pd_daily_stats` | 每日里程汇总 |

`pd_daily_stats` 需要支持 `appid`、`dayKey`、`distance`、`_id` 的榜单查询组合索引，具体顺序和迁移步骤见[统计说明](遛狗记录与每日排行榜修复说明.md)。其他查询如提示索引缺失，按云数据库控制台提示创建。

统计集合应禁止客户端直接读写，通过云函数鉴权访问。`pd_users` 的现有客户端逻辑需读取地图名片及保存自己的档案；`pd_markers` 需读取附近标记并新增自己的标记。应结合实际交互配置最小权限：禁止改写其他用户档案或标记，不向公开可读文档添加联系方式等私密字段。云函数使用服务端上下文获取身份，不信任客户端传入的身份字段。

当前名片查询使用标记关联的 `_openid`，因此地图数据并非匿名数据；如需进一步隐藏用户标识，应先将名片读取迁移到云函数并返回最小展示字段。

## 云存储

公开仓库只包含四张导航图标。其余素材需自行准备或使用自己拥有使用权的替代素材，文件名与大小写需一致。

- `UI/`：11 张插画，完整映射见 [UI 文档](UI素材云存储迁移说明.md)。
- `avatars/`：`corgi.png`、`golden.png`、`schnauzer.png`、`bichon.png`、`teddy.png`、`border_collie.png`、`akita.png`、`tianyuan.png`、`random_dog_1.png` 至 `random_dog_3.png`、`cat_1.png` 至 `cat_3.png`。

将控制台提供的真实文件 ID 根前缀填入本地 `storageBaseUrl`，不要仅凭环境 ID 猜测存储桶前缀。图片服务通过 `getApp().cloud` 解析临时 URL。检查公共展示素材的读取权限和跨账号授权，避免开放存储写权限。

## 验收

依次验证身份与档案、地图定位及打卡、标记过期清理、图片读取、遛狗开始与结束、后台与恢复、跨午夜统计以及每日排行榜。真机测试前需在微信公众平台配置定位相关能力与隐私保护指引。
