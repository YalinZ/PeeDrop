# 留味儿：统一宠物头像

本地代码已替换；云函数部署、真实云文件及读取权限仍需在微信开发者工具和资源方云环境验证。

## 旧逻辑与替换范围

- `pages/user/user.js` 中删除旧 `avatarMap`、`randomAvatars`、`getDogAvatar`。旧文件名包括 poodle、Bichon_Frize、Schnauzer、rural_dog、random1…random6、cat，不符合新云存储命名。
- 个人档案与排行榜 WXML 不再硬编码本地柯基兜底，改为统一 `pet-avatar` 组件。
- 原地图名片只有文本，现在从档案统一映射并展示头像，查询失败、过期响应、页面离开均有处理。
- 原 `pd_daily_stats` 只包含名字和品种；新云函数保存并返回 `petId`、`petType`、`petBreed`，数据库内部同时保存 `profileId`。
- 保存档案只写业务字段；不保存计算得到的头像地址，更新旧档案时删除旧 `avatarUrl` 字段。
- 独立装饰插画继续作为装饰使用，不参与宠物身份匹配。

## 匹配规则

工具：`miniprogram/utils/pet-avatar.js`。

```js
getPetAvatarUrl(petId, petType, petBreed)
```

基础前缀固定为：

```text
cloud://YOUR_CLOUD_ENV_ID.YOUR_STORAGE_BUCKET/avatars/
```

狗的精确品种对应 `corgi.png`、`golden.png`、`schnauzer.png`、`bichon.png`、`teddy.png`、`border_collie.png`、`akita.png`、`tianyuan.png`；其他品种使用三个 `random_dog_N.png`。猫始终使用三个 `cat_N.png`，不经过狗的品种字典。

Hash 使用字符串字符码、31倍累积和无符号32位取模，兼容中文。头像逻辑没有 Math.random。ID支持字符串和有限数字，包括0。

类型接受 dog/狗/狗狗/犬、cat/猫/猫咪/猫猫，英文忽略大小写并去掉两侧空格。缺失或未知类型默认狗。数据适配层额外兼容旧记录 `breed: '猫'` 且没有显式类型的情况；显式 dog 不会被品种覆盖。

`toPetProfile` 兼容 `petType/type`、`petBreed/breed`。身份优先采用 `petId`，档案可回退 `_id`，最后才用名字。名字缺失时使用固定默认种子。未保存的新档案先按名字预览；保存生成档案ID后重新映射，以后改名不改变同品种随机头像。

排行榜必须使用 `toPetProfile(row, { useDocumentId: false })`，其 `_id` 属于每天的统计文档，不能用来确定头像。

## 云端与历史数据

`cloudfunctions/walkStats/pet-profiles.js` 优先按 `profileId` 批量读取当前档案，使改品种、改猫狗类型后榜单也使用当前匹配规则。公共榜单只返回展示字段和宠物ID，不返回用户 OPENID。

旧统计没有档案ID时，服务端按现有 owner 哈希验证归属，分页读取档案关联；不会根据同名宠物猜测。找到后仅回填头像关联字段，不修改距离、排名、姓名快照。第一次兼容查询可能比平时慢，后续按档案ID读取。

当前项目是一位用户一份宠物档案。若历史上存在同一用户的重复档案，应先清理重复记录；原按用户汇总的统计不能可靠区分多只宠物。档案已删除、又缺少历史宠物ID时，退化为名字哈希，无法凭空还原被删除的ID。

## 渲染与错误处理

页面的 `avatarUrl` 始终是指定前缀的 cloud 文件ID。`components/pet-avatar` 使用现有跨账号 `app.cloud` 实例，通过 `getTempFileURL` 获取用于渲染的 HTTPS 链接。

- 同一批次的文件请求合并，相同文件共享在途请求。
- HTTPS链接仅在内存缓存，最长5分钟，不写入数据库或本地长期存储。
- 单个文件失败不会使同批其他头像失败；失败结果不缓存。
- 图片用 aspectFit，透明插画不裁切。
- 错误展示“重试”，用户点击重新获取链接，始终重试同一个文件，不换成另一种宠物或循环重试。
- 旧请求、组件销毁后的回包不会覆盖新头像。

## 部署与验收

1. 在资源方环境确认 `avatars/` 下14个文件存在，文件名大小写一致，特别是 `bichon.png`、`schnauzer.png`、`teddy.png`、`tianyuan.png`。
2. 文件还包括 `random_dog_1.png` 至 `random_dog_3.png`、`cat_1.png` 至 `cat_3.png`。
3. 将整个 `cloudfunctions/walkStats` 上传并部署，包含新增的 `pet-profiles.js`，继续选择项目 `resourceEnv` 对应的跨账号资源环境。
4. 确认跨账号资源共享允许读取这些公共头像素材；不要为了头像开放整个云存储的写权限。
5. 编译前端，确认 user.json 和 map.json 已注册 `/components/pet-avatar/index`。当前版本已完成注册。
6. 检查个人页、编辑预览、榜单、地图名片；同一已保存宠物应显示同一头像，未知狗品种和猫改名后保持同一选择。
7. 再测试猫配“柯基”品种仍使用猫头像、空品种狗使用随机狗、图片无读取权限时可重试且不换宠物。

本地测试：`node --test tests/*.test.js`。测试使用SDK替身，不代表云存储真实权限或所有文件已经验证通过。
