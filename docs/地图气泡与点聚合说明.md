# 地图Emoji气泡与密集聚合（当前实现）

已根据反馈恢复原生callout Emoji气泡，移除上一版customCallout插槽及map-bubble样式。定位、遛狗、打卡写入、名片内容及外部控件位置不变。

## 展示规则

- 单点：显示原打卡类型对应的Emoji，白底、大圆角，配置2px黑色描边。
- 完全相同坐标：按createTime选最新记录，点击读取该记录的主人与留言；不删除历史数据库记录。时间相同按_id稳定选择，时间缺失排在有时间的记录之后。
- 相近但不完全相同的坐标：保留独立记录，由原生点聚合控制密集展示。
- 聚合：黄色气泡显示真实类型Emoji（最多3种）与数量，例如“💩 💦 🐕 ×6”。数量为同坐标去重后的显示点数，不是去重人数。
- 点击聚合放大展开；删除上一版同坐标菜单，因为同坐标只显示最新一条。

## Emoji对应

poop 💩 拉粑粑；pee 💦 尿尿；edog 🐕 e狗求玩；idog 🫣 i狗勿扰；danger 🛑 烈性犬；poison ☠️ 有毒物；police 🚓 查狗队；cat 😼 猫猫怪物出没；grass 📍 宝藏草坪；cafe ☕ 宠物友好。

## 可见性处理

map.wxml恢复markers="{{markers}}"。每个标记直接携带callout，不再依赖customCallout插槽，也不会在等待聚合初始化时向地图绑定空列表。

支持原生聚合时，addMarkers在视图更新后同步同一批数字ID并清除旧点；创建聚合点携带原生clusterId、独立数字ID与joinCluster:false。初始化失败会关闭joinCluster并继续显示普通Emoji。

## 查询

保留3公里geoNear查询，改为每页100条读取，直到附近结果读完；每次请求返回都检查页面销毁和请求序号，避免旧数据覆盖。这样默认首批结果外的同坐标最新记录也能参与比较。只影响读取和展示，不改变打卡写入。

大量数据时完整翻页会增加读取量；如后续附近积累大量历史记录，可以在独立任务中增加云端按坐标取最新的聚合查询，当前未修改后端或数据权限。

- miniprogram/pages/map/map.js：附近查询分页。

## 操作

1. 保存并重新编译，不清空存储。
2. 在同一位置分别打卡尿尿、拉粑粑，确认只显示最后一次对应的Emoji；点击检查最新留言。
3. 在不同位置打卡，缩小地图检查Emoji聚合，点击后展开。
4. 在iOS/Android真机预览。原生气泡描边及聚合效果以真机为准。

无需上传新图片、修改数据库或部署云函数。前端验证后再上传新版本。

自动测试使用地图SDK替身，不能代替真机验收。
